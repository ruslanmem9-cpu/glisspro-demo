# Чеклист приёмки (п. 12 ТЗ)

Проверяется на демо (`index.html`) и после запуска на Tilda. Отметки ставит заказчик или тестировщик.

## Адаптивность

- [ ] Главная, каталог, карточка, корзина, оформление открываются на десктопе (от 1280 px).
- [ ] Те же страницы корректно выглядят на телефоне (от 360 px), меню открывается и закрывается.
- [ ] Hero-изображение на главной занимает весь экран по ширине.

## Каталог, поиск и фильтры

- [ ] Категории переключаются, счётчик «Показано: N» меняется.
- [ ] Поиск по названию и артикулу находит товар; пустой результат показывает сообщение.
- [ ] В боевой версии (Tilda): фильтры по категориям и поиск работают на всех 104 позициях.

## Варианты и количество

- [ ] Товары с вариантами (объём, количество в упаковке) показывают правильную цену для каждого варианта.
- [ ] Количество в карточке и в корзине меняется кнопками и вручную, минимум 1.

## Сравнение

- [ ] Кнопка «Сравнить» добавляет товар; больше трёх товаров не добавляется.
- [ ] Таблица сравнения показывает характеристики и цену «от»; товар удаляется кнопкой «Убрать».

## Скидка 10% на первый заказ

- [ ] Скидка видна в корзине (ориентировочно) и на оформлении (итог).
- [ ] Первый заказ по телефону или email получает скидку; повторный заказ с тем же контактом скидку не получает.
- [ ] Скидка передаётся в данных заказа (поля `amounts.discount`, `first_order`).
- [ ] Для физлиц, компаний и ИП скидка одинаковая.

## Корзина

- [ ] Добавление, изменение количества, удаление товара, пересчёт итога.
- [ ] Пустая корзина показывает сообщение и ссылку в каталог.

## Все способы оформления

- [ ] Физлицо: поля контактов, телефон обязателен.
- [ ] Компания или ИП: открываются поля названия и ИНН, ИНН проверяется по формату (10 или 12 цифр).
- [ ] Транспортная компания: город, адрес или пункт выдачи, комментарий.
- [ ] Доставка по Санкт-Петербургу: адрес, дата, комментарий.
- [ ] Самовывоз: выбор пункта выдачи из списка.
- [ ] Доставка во всех способах показана как 0 ₽.
- [ ] Заказ с согласием создаётся, корзина очищается, появляется номер заказа.

## Оплата и платёжные статусы

- [ ] Онлайн-оплата: статус после создания «Ожидает оплаты».
- [ ] Статус «Оплачен» появляется только при подтверждении от платёжного сервиса (webhook), не при возврате на страницу результата.
- [ ] Обработаны успешная, неуспешная и отменённая оплата.
- [ ] Заказ по счёту: статус «Ожидает счёт», без онлайн-оплаты.
- [ ] Тестовая покупка проведена в тестовом режиме платёжного сервиса.

## Передача данных в CRM

- [ ] В amoCRM попадают контакты, тип покупателя, источник и страница, товары с вариантами и количеством.
- [ ] Передаются сумма, скидка, способ оплаты, способ получения и адрес, комментарий, статус оплаты.
- [ ] Заявки из форм (консультация, вопрос о товаре, партнёрские условия, общее обращение, заказ по счёту) создают сделку с правильным типом.

## Формы и сообщения об ошибках

- [ ] Пустые обязательные поля подсвечиваются, браузер или сайт показывает понятное сообщение.
- [ ] Неверный формат телефона, email и ИНН блокирует отправку.
- [ ] После отправки показывается подтверждение.

## Ссылки и аналитика

- [ ] Все внутренние ссылки открывают нужную страницу; нет страниц с ошибкой 404.
- [ ] Яндекс Метрика установлена, цели настроены: отправка формы, добавление в корзину, оформление заказа, подтверждённая оплата, клики по телефону.
- [ ] Редиректы со старых адресов работают.
- [ ] HTTPS включён, почта на домене получает письма.

## Передача

- [ ] Переданы доступы (Tilda, домен, Метрика, amoCRM, платёжный сервис).
- [ ] Передан код (если использовался) и инструкция `docs/instrukciya-kontent.md`.
